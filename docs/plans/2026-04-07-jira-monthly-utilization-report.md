# План: Месячный отчет по утилизации Jira

Дата: 2026-04-07  
Тип задачи: Новая функция

## Architect

### Цель и границы
- Добавить в `Утилизация Jira` отдельную подвкладку `Месячный отчет`.
- Дать возможность загрузить 5 недельных файлов выгрузки Jira (обязательные: 1-4 неделя, 5 неделя опционально).
- Добавить ввод значений утилизации за предыдущие месяцы для таблицы `Динамика утилизации`.
- Добавить кнопку формирования месячного отчета, сохранение отчетов и просмотр ранее сформированных отчетов.

### Затрагиваемые модули
- Frontend:
  - `frontend/src/pages/JiraUtilizationPage.jsx`
- Документация:
  - `docs/plans/2026-04-07-jira-monthly-utilization-report.md`

### Риски и миграции
- Риск: некорректный формат Jira-файла на одной из недель.
  - Снижение риска: валидация обязательных колонок и явные ошибки.
- Риск: потеря истории отчетов при изменении структуры хранения.
  - Снижение риска: версионированный ключ localStorage.
- Миграции БД/структур коллекций: не требуются.

### Rollback
- Удалить добавленную подвкладку и связанный код в `JiraUtilizationPage.jsx`.
- Удалить ключи localStorage, связанные с месячными отчетами (опционально).

### Критерии приемки
- В `Утилизация Jira` доступна подвкладка `Месячный отчет`.
- Можно загрузить 4 обязательных и опционально 5-й недельный файл.
- Можно указать значения по месяцам для блока `Динамика утилизации`.
- Кнопка `Сформировать отчет` строит данные и сохраняет отчет.
- Список сохраненных отчетов доступен, отчет можно открыть и скачать.

### Проверки
- Ручной чек-лист UI/поведения (см. секции Tester ниже).

## Implementer (change-log)
- Что изменено:
  - `frontend/src/pages/JiraUtilizationPage.jsx`:
    - Добавлена подвкладка `Месячный отчет` в `Утилизация Jira`.
    - Реализована форма загрузки недельных Jira-файлов: 5 слотов (1-4 обязательные, 5 опциональная).
    - Добавлен блок ввода истории утилизации по месяцам для таблицы `Динамика утилизации`.
    - Добавлена кнопка `Сформировать отчет`.
    - Добавлено сохранение/чтение отчетов в `localStorage` (`jira_util_monthly_reports_v1`).
    - Добавлен список сохраненных отчетов с действиями `Открыть`, `Excel`, `Удалить`.
    - Реализован экспорт месячного отчета в `.xlsx` (лист `Трекинг времени`).
    - Вынесен общий парсинг Jira-файла в `parseJiraExportFile`.
- Почему:
  - Требовалась отдельная механика месячной сборки по 4/5 неделям и хранение сформированных отчетов с повторным просмотром.
- Как проверить вручную:
  1. Открыть `Утилизация Jira` → `Месячный отчет`.
  2. Выбрать месяц, загрузить 4 файла (недели 1-4), при необходимости 5-й файл.
  3. Заполнить утилизацию по предыдущим месяцам.
  4. Нажать `Сформировать отчет`.
  5. Проверить появление карточки активного отчета и записи в `Сохраненные отчеты`.
  6. Нажать `Excel` и проверить скачивание файла.
  7. Нажать `Открыть` для существующего отчета и убедиться, что он отображается.
  8. Нажать `Удалить` и убедиться, что отчет удаляется из списка.
