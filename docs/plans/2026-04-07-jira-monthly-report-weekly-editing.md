# План: Редактирование недель в месячном отчете Jira

Дата: 2026-04-07  
Тип задачи: Новая функция

## Architect

### Цель и границы
- Для сохраненных месячных отчетов добавить интерфейс просмотра отчетов по неделям.
- Добавить редактирование значений сотрудников в неделях.
- Добавить удаление сотрудников из конкретной недели.
- Пересчитывать месячный отчет на основании отредактированных недельных данных и сохранять результат.

### Затрагиваемые модули
- `frontend/src/pages/JiraUtilizationPage.jsx`
- `docs/plans/2026-04-07-jira-monthly-report-weekly-editing.md`

### Риски и миграции
- Риск: ломка формата ранее сохраненных отчетов в localStorage.
  - Мера: обратная совместимость чтения отчетов (если нет новых полей — инициализация по умолчанию).
- Риск: ошибки пересчета после редактирования значений.
  - Мера: единая функция пересчета итогов из недельных employee-данных.
- Миграции БД не требуются.

### Rollback
- Удалить UI и логику недельного редактирования в `JiraUtilizationPage.jsx`.
- Вернуться к прежнему формату сохранения месячного отчета.

### Критерии приемки
- При открытии сохраненного отчета видно данные по неделям.
- Можно изменить значения категорий по сотруднику в неделе.
- Можно удалить сотрудника из недели.
- После сохранения изменений месячные итоги пересчитаны из недельных данных.
- Обновленный отчет сохраняется и повторно открывается с изменениями.

## Implementer (change-log)
- Что изменено:
  - `frontend/src/pages/JiraUtilizationPage.jsx`:
    - Добавлен пересчет месячного отчета из недельных employee-отчетов (`recalcMonthlyFromWeekly`).
    - Добавлено отображение недель при открытом месячном отчете.
    - Добавлен редактор недельных отчетов (`WeeklyEmployeesEditor`):
      - inline-редактирование часов по категориям для сотрудника;
      - удаление сотрудника из выбранной недели.
    - Добавлена пересборка месячных агрегатов в UI при любом изменении недельных данных.
    - Добавлена кнопка `Сохранить изменения` для фиксации отредактированного месячного отчета в истории.
- Почему:
  - Нужно редактировать данные на уровне недель и строить месячный итог из уже исправленных недельных значений.
- Как проверить:
  1. Сформировать месячный отчет.
  2. Открыть блок `Недельные отчеты (редактирование)`.
  3. Изменить значения категорий у сотрудника.
  4. Удалить сотрудника из недели.
  5. Убедиться, что средняя утилизация месяца пересчитывается.
  6. Нажать `Сохранить изменения`, перезагрузить страницу и открыть отчет заново.
  7. Проверить новый ввод `Норма часов за неделю` для каждой недели.
  8. Изменить нормы по неделям и убедиться, что `%` и `Итого` считаются по недельной норме, а месячный итог — по сумме недельных норм.

- Дополнение (по запросу пользователя):
  - Добавлена отдельная норма часов для каждой недели при формировании отчета.
  - Добавлено редактирование нормы внутри открытого недельного отчета.
  - Пересчет месячных агрегатов переведен на сумму недельных норм вместо нормы месяца.

## Tester
- Что проверено:
  - `cd frontend && npm run build` — успешно.
  - Lint/диагностика для `frontend/src/pages/JiraUtilizationPage.jsx` — без ошибок.
- Ручной чек-лист:
  1. В `Утилизация Jira` → `Месячный отчет` сформировать новый отчет.
  2. Открыть отчет и убедиться, что есть переключение по неделям.
  3. Изменить часы у сотрудника в любой категории.
  4. Удалить сотрудника и проверить обновление показателей.
  5. Нажать `Сохранить изменения`.
  6. Обновить страницу, открыть сохраненный отчет и проверить, что правки сохранены.
  7. Установить разные нормы по неделям (например 40/32/40/24), затем проверить:
     - в неделе проценты считаются по ее норме;
     - в месяце суммарная норма равна сумме недель;
     - изменение нормы в редакторе недели сразу обновляет месячные показатели.
